## 图片识字

传送门图片拖拽菜单、中转站图片、分词面板重新识字及系统图片分享可进入图片识别。ImageOcrOverlay在模块进程创建独立悬浮窗，解码后最长边4096像素，使用软件Bitmap。成功进入BigBangOverlayLauncher独立分词窗，保留来源图片以便重新识别；错误在当前窗口显示原因，提供重试/取消。系统分享接收使用透明ImageOcrActivity暂存输入URI后退出，不展示设置首页。传送门不因识字新增作用域。

1.7.97中转站图片→308字符原页浮窗已有设备证据；1.7.111以生成中英三行图片测试实际AICR产品路径，显示38字符分词窗，前台仍是bilipai。各应用图片拖拽入口仍需分别验收。

1.7.117补齐传送门面积候选的Root图片分支：只接受明确图片节点，完整检查密码区域后才确认候选；Root截图后再次核对锁屏、来源窗口ID/包名及完整显示尺寸，再裁剪所选区域。通过既有PNG暂存与recognize_image_window请求复用图片OCR浮窗，不增加作用域，不打开模块Activity。截图与系统保护层行为沿用RootScreenshotter，不修改权限或安全窗口。

生成图片真机实验取得1392×773节点区域，AICR输出83字符分词窗，前台Activity保持独立样本页；普通文字对照未被带入。原图“·”识为“-”，不标识别准确率通过。该实验直接调用真实Root取图客户端，未模拟面积，也未证明Portal UID暂存、180ms确认、接管原长按及完整手指流程通过。图片不发送早期候选；复杂节点树若超原生长按期限，保留原手势。

## 引擎与生命周期

- 默认使用随包ML Kit中文模型，用户可选择系统AICR V2（实验）；不在失败后静默切换。
- AICR普通应用UID直接绑定当前ROM已核验的Core/视觉服务，按setImage→detect→recognize调用并释放连接，不把小爱能力Provider当OCR。协议和设备证据见 AICR_OCR_FEASIBILITY.md。
- AICR同进程一次请求。取消标记不伪装成中断同步Binder；回调在真实调用及清理结束后发送，调用方此时才回收图片。15秒仅限制等待连接，不限制整个同步Binder调用。
- ImageOcrOverlay窗口关闭后不发布迟到结果；ML Kit与AICR均在读取结束后释放各自资源。图片读取、权限、服务和识别失败有明确日志/界面反馈，不记录用户识别全文或完整URI。

## 屏幕与追加文字

整屏和区域快捷磁贴、背敲（默认关闭）、分词更多菜单“追加屏幕文字”已接入Root/无障碍截图路径。区域页可手动框选，原文位置只作参考，不猜测滚动后的文字；结果按行选择或全部追加，保留旧词边界/选区，取消恢复原会话。ML Kit提供行范围，AICR目前只返回文字行，不返回产品可用的几何范围。

屏幕识字已抽取为 `ScreenOcrOverlay` / `ScreenOcrSession`：选区、识别进度、结果和确认均由独立悬浮窗承载，`ScreenOcrActivity` 只为快捷磁贴和背敲保留透明请求桥，转交后立即退出；内部“追加屏幕文字”直接调用对象，不启动模块 Activity。原选区/结果组件与 ML Kit、AICR 生命周期共用一套实现。

- `ScreenOcrOverlay.start(context, selectRegion, resultReceiver, sourceArea, beforeCapture)` 先检查悬浮窗权限和锁屏；接受后同步执行 `beforeCapture` 关闭来源分词窗或透明桥，延迟120毫秒等待窗口移除，再在工作线程执行一次受限 Root 截图。取得截图后才显示 OCR 窗口，重新识别也先移除自己的窗口。没有权限时保留原分词窗并提示，不静默转入 Activity。
- 区域模式显示冻结截图供框选；结果面板使用现有 Miuix 浮窗容器，竖屏高度上限为屏幕68%，长结果在窗内滚动。全屏/区域两模式保留原引擎选择；AICR 失败不会悄悄换用 ML Kit。
- 追加识别结果按行选择，确认后通过 `ResultReceiver` 返回文字，原流程追加并恢复之前的词边界及选区。取消/返回发送取消结果，恢复原分词；息屏发送 `restore_panel=false`，不重新呼出分词。截图或窗口失败明确提示，迟到的截图和识别结果不会创建新窗口。
- ML Kit 和 AICR 都保留正在读取的 Bitmap 到真实完成回调后才回收。关闭先移除浮窗、取消待截图任务及 AICR 请求；截图工作线程、广播、原图及裁剪图均由同一会话释放。AICR 同步 Binder 调用仍不能被强制中断，此限制未改变。
- 区域快捷入口成功后进入独立分词窗；全屏入口保留按行分词、复制、分享和重新框选。分享由用户主动发起系统分享菜单，同时关闭 OCR 窗口，避免覆盖分享界面。

1.7.114真机：内部追加截图不含来源分词窗和更多菜单；取消恢复已选7/16，AICR区域识别后追加为7/25，旧选词保留。AICR整屏返回8行；ML Kit整屏返回9行，点某行进入8字符独立分词窗。区域ML Kit样本仅识别5/8字，整屏同一标题还出现“睛→晴”，识别质量仍有缺陷；不把成功回调当准确率通过。前台Activity始终为bilipai，未展示模块页面。息屏、旋转、重试、磁贴/背敲实际触发、ML Kit附近推荐、原图URI授权仍待实测。磁贴/背敲入口不会自动清除其他类型的模块悬浮窗；内部追加已明确移除来源分词窗。

无障碍模式长按后没有可用节点时，在黑名单、锁屏、密码区域与图片开关检查通过后，可截取触点附近最多360×220dp区域进入图片拖拽。该后备路径区别于用户主动框选；传送门模式不自动截取整屏。真实拇指面积的Root图像分支仍未实现，不以普通长按代替。
