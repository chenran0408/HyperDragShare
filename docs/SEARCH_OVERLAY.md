# 原页搜索、查词与翻译

## 当前实现

- 从分词悬浮窗进入搜索、词典或翻译时，`BigBangOverlayLauncher` 直接打开 `SearchOverlayWindow`，窗口类型为 `TYPE_APPLICATION_OVERLAY`，不启动模块 Activity。
- 原分词会话及选词状态保留在下层。关闭搜索直接回到原分词窗口，不重新分词或重建选择。
- `SearchOverlaySession` 是唯一的查询、引擎选择、WebView、网页导航和搜索面板实现；`SearchOverlayActivity` 仅保留旧分词 Activity 的兼容入口及生命周期管理，没有复制另一套搜索逻辑。
- 返回键依次处理输入法、网页历史、搜索窗口关闭；明确点击关闭或面板外部会关闭搜索。输入查询后提交和切换搜索引擎会收起输入法。
- 搜索框可编辑文字或输入 HTTPS 网址。保留百度、必应、Google、维基百科、有道词典、必应词典、金山词霸、有道翻译和百度百科。
- 保留顶部拖动调整高度、前进、后退、刷新和主动转到浏览器。高度仍保存在原 `search_overlay` 私有偏好中，原用户的高度选择不变。
- 搜索面板使用 Miuix，与浅色、深色、跟随系统设置一致。系统配置变化由 Compose 的 `LocalConfiguration` 观察。

## 窗口与资源边界

- 悬浮窗权限不足、锁屏时不打开搜索，显示原因；窗口或 WebView 创建失败会记录错误并显示提示，保持原分词窗口，不切换到 Activity 兜底。
- 息屏时关闭搜索；来源分词窗口被移除时一并关闭搜索。此路径只释放资源，不自动创建或恢复新窗口，因此锁屏不会重新呼出分词。
- 关闭会清除焦点、请求收起输入法、停止网页加载、移除并销毁 WebView，注销广播及来源窗口监听。
- 用户主动点击“在浏览器打开”时，走分词宿主原有的外部应用跳转流程：保存原分词状态、关闭这两层窗口并显示返回条，避免系统悬浮窗盖住浏览器。搜索窗口自身不会静默启动其他页面。
- WebView 只加载 HTTPS，禁用文件、content URI、混合内容、自动新窗口和 JavaScript bridge；JavaScript 只用于站点自身页面。网络或 TLS 失败显示错误状态，TLS 错误明确取消请求。
- 查询文字会发送给用户当前选择的搜索站点。网站内容、结果及可用性由该站点决定。

## 当前验证状态与验收项

1.7.113 / 137已构建安装，172项测试、Lint通过。真机已验证百度结果、有道词典页面、中文翻译结果，前台仍bilipai；编辑查询弹键盘、返回先收键盘、关闭返回原选区通过。具体记录见DEVICE_VALIDATION.md。以下为完整验收范围，未列为已验证的仍待验证：

1. 分词浮窗的搜索、查词、翻译均不新增模块 Activity；关闭后选词仍保持。
2. 编辑查询可调出键盘，提交能收起；返回先收键盘，再网页后退，最后关闭搜索。
3. 网络失败、网页刷新与前进后退、拖动高度调整。
4. 浅色、深色、跟随系统切换；搜索打开时切换系统夜间模式。
5. 息屏、来源分词窗口移除和反复打开关闭后，无残留窗口或 WebView。
6. 主动跳转浏览器时不会被分词窗口盖住，返回条能恢复原选择。

现有 `SearchEngineTest` 覆盖默认引擎、UTF-8 查询编码、HTTPS 识别及非 HTTPS scheme 拒绝。统一检查命令：

```powershell
.\gradlew.bat testDebugUnitTest lintDebug assembleDebug
```
