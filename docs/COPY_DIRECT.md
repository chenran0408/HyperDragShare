# 复制直达与原页分词联动

## 174 实现

传送门复制卡片“编辑所选文本”与AICR TextDirectProvider/processText入口继续受已有默认关闭开关控制。入口明确拿到文字并被模块接受后，在原页分词窗显示实体建议；普通分词也可点链接图标，对当前选区（未选则全文）主动识别。只分析该次明确传入文字，不注册模块剪贴板监听、不读取空闲窗口。

实体建议是现有浮窗内的紧凑卡片，可关闭，关闭不清文字或选区。链接、电话、邮箱由用户点按后交给相应应用；其他实体使用已有原页搜索。不会自动拨打、发信或执行链接。不是小爱全量识屏，也不是把能力查询Provider当实体接口。

AICR 4.12.26/2030041226静态核对：Core插件管理器w87.j明确注册INerService/V1；Core事务1取得插件、事务2释放连接；NER事务1接收String并返回Entity typed list。独立按协议读取String、type、start、end，不加载厂商Parcelable或复制反编译实现。系统cut方法未实现，因此不替换现有cppjieba拆词。普通UID权限与真实模型结果需单独记实机证据。

TextDirectProvider本身仅返回success，不返回实体/动作；原系统复制直达含能力1210门控及业务通知跳转，当前没有复制这些私有业务动作，不伪造系统权限或强制开启其能力。

## 浏览器与本地链接

明确的整值http(s)链接直接生成本地查看动作，不依赖NER返回网址。复合文本仍走系统NER，没有把本地规则称为AICR实体识别成功。现有Miuix更多页可选择已装通用浏览器，默认跟随系统；仅复制直达URL动作和其搜索结果外部打开应用该设置，邮件/拨号及其他功能不改路由。所选浏览器卸载/无法处理网页时明确提示重新选择，不静默换到别家。

参考HyperCopy_v1.8_R8.apk的只读定点分析确认其URL/规则匹配与NER是不同能力；只借鉴本地匹配和显式目标路由方向，没有复制其反编译、回写剪贴板、通知或多级回退逻辑。

## 连接与失败

NER单请求，回调主线程；关闭建议取消请求，同步Binder返回后释放Core并解绑。权限、服务/模型状态、协议失败显示明确原因，不切换引擎、不重试。日志只记录实体数量、阶段和耗时，不记录原文。

当前源码接线已完成；构建、安装与普通UID调用结果见CURRENT_STATUS/DEVICE_VALIDATION的174条。类型识别和Intent能创建不等于目标应用实际打开通过。

## 实机证据（174）

最终R8包普通模块UID成功提取测试号码：1个实体/316ms。URL测试系统NER为0项，本地URL规则能生成查看链接建议；关闭建议后正文和19/19全选保留。没有发起通话、邮件或网络链接。指定浏览器实际跳转、复制卡片自动触发和复合实体仍待体验，不能将Intent构造或Hook加载当成通过。
