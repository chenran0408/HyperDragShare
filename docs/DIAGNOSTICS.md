# 问题反馈与诊断

当前交付版本、提交和实际验证只见[CURRENT_STATUS](CURRENT_STATUS.md)。本文维护入口、文件格式和隐私/生命周期约定。

## 页面和代码地图

- 通用设置的唯一可见入口为“问题反馈与诊断”；搜索日志、报告、反馈、触控均可定位。`SettingsCatalog.unifiedDiagnosticsEntry`的同一份元数据供页面和搜索使用；旧log.export、gesture_compatibility_report、gesture_feedback、touch.probe标识归到同一目标，旧重复行不再显示。
- 原状态诊断页保留分环节证据及处理入口，新增通往统一页的链接，不将Root、模块、输入或OCR合成一个授权结论。
- `ProblemDiagnosticsPage`：生成诊断ZIP、选择保存位置、分享同一文件；用户主动打开日志设置或反馈网址。缺少日志仍可导出，不自动修改设置。
- `DiagnosticBundleExporter`：独立收集已有兼容报告、版本/环境与安全状态摘要、受控日志；单项失败不使其他信息丢失。调用既有有界文件日志读取，不新建Root检查、内容捕获或常驻监控。
- `DiagnosticExportSession`：页面本次生成/保存/打开分享面板的代次与一次性结果消费。统一页和触控专项复用；状态是页面局部的，不决定实际功能权限或动作成功。
- `TouchProbeActivity`：底部固定“导出触控报告”，不再提供三组手动附库选项。导出仅受正在按压采集/正在导出的必要限制；不依赖连接、样本或算法校验通过，算法校验和采样条件保留。
- `TouchProbeExporter`：每次重新发现当前设备库映射，SHA-256精确命中已知库则仅报告，不匹配且哈希可用则尝试附库；不再按曾导出过该哈希的缓存省略后续附件。复制后沿用SHA-256、ELF、架构与大小校验，只有通过的库进ZIP；这不是采样/解码许可。没有恢复触摸面积算法研究。

## 导出流程

点击导出 → 在原worker/IO生成一次文件 → 系统保存选择器 → 写入用户选择位置 → 打开系统分享面板，复用同一文件。专项按原Result类型使用text/plain或application/zip；统一包使用application/zip。取消保存清本次等待状态，不打开分享；保存失败、分享面板打开失败分别提示。打开分享面板不等于已经上传/发送。

重复点击不重复生成；Picker结果只消费一次；页面退出使token失效，迟到生成或保存结果不再更新UI/打开面板。阻塞工作允许按既有有限过程返回，使用applicationContext；文件与流在既定owner处关闭。未将已生成报告文件提前删除，以免分享接收端失效。

FileProvider继续使用现有`${applicationId}.updates`、read grant、EXTRA_STREAM和ClipData。只新增cache/diagnostics窄目录，原cache/touch-probe目录不变；没有修改媒体分享Provider、权限校验或拖拽资源释放。

## 统一ZIP格式

| 条目 | 内容/可用条件 |
|---|---|
| summary.txt | 版本/版本码、设备环境和当前ActivationSnapshot枚举摘要；无状态时明确不可用 |
| compatibility.txt | 既有CompatibilityReport的设备、组件版本、非敏感数值配置等受控字段；生成失败可缺失 |
| runtime-log.txt | 能读取文件日志时，保留受控OperationTrace和logger头；没有合规记录时可缺失 |
| manifest.txt | 每项included/unavailable、缺失原因、开启文件日志后复现的建议、隐私过滤说明 |

日志关闭、设为系统日志、Root不可读取、无文件或只有被隐私过滤的自由文本时，summary与manifest仍可生成。用户自行选择是否开启文件日志后复现，不在导出时自动更改配置。既有状态是快照，不进行新的探测以伪装确定结论。

## 隐私与追踪上限

ZIP不打包用户正文、图片、截图、剪贴板、原始敏感URI或授权令牌。运行日志仅保留既有受控格式的proc/op/stage/outcome/asset及描述符unknown字段；自由文本、异常消息/堆栈和非受控Hook文本过滤，并在manifest说明。因此它是可反馈的过滤日志，不是完整原始日志副本。

旧日志先归档后当前，过滤器在大小预算内保留最新受控记录，避免旧前缀占满预算导致漏掉最近操作。日志缺失不能直接判失败；activity_launch_returned、drop接受、descriptor_opened各有证据上限，读取与最终发送无回执时未知。两条实际链路与判读规则见[OPERATION_TRACING](OPERATION_TRACING.md)。

专项触控报告保持原设备/库身份、失败原因与已有样本字段；算法库仍须原校验和复制路径。能导出报告不意味着可以安全采样或解码，不能为了导出绕过校验。

重新发现失败时仍用最近连接身份保留报告信息及失败原因，禁止拿陈旧映射继续复制。缺少哈希时说明无法判断并生成基础报告；附库复制/验证失败时保留原报告与失败说明，不把无校验文件打包。报告记录`library_policy=attach_when_hash_differs_from_known_library`，不再输出旧手动选项字段。

## 验证和用户回归

新/既有测试覆盖完整与缺失源ZIP、日志关闭/系统目的地且配置不变、受控日志和隐私过滤、最新记录保留、真实生产入口搜索、重复/取消/迟到/save与chooser失败，以及触控各失败状态的报告内容与导出收尾。真实Miuix布局、系统保存选择器和分享端读取属于后续设备验收，不能用逻辑测试替代。

用户最小复现步骤：

1. 通用设置 → 问题反馈与诊断，日志未开启也先导出一次；确认ZIP能保存并打开。
2. 需要记录问题时，主动进入日志设置开启文件日志，重载所需作用域后复现，再导出ZIP；结束后可恢复原日志设置。
3. 触控诊断在未开始、连接失败或算法不匹配时检查底部按钮；取消保存、再导出，不应一直显示处理中。不要尝试绕过算法校验。
4. 中转站独立入口与安全中心入口分别拖同类图片至微信/QQ，记下入口、时间、落点、拖影是否结束、目标是否变化；无须把私人原图附给报告。用ZIP判断最后确认阶段，目标最终发送仍需人工确认。
