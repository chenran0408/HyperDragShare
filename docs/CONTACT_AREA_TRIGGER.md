# 拇指接触面积：实现与证据

本文件记录本 fork 的实验和行为参考；不包含参考 APK 的反编译代码。目标设备为小米 15 Pro / HyperOS 4.0.0.17 / Android 17。

## 1.7.140 按压流程重写（真机手感未验收）

用户要求以参考行为整体重写，已删除校准Activity、校准计算与旧180ms检测器、两套独立面积CaptureSource。现在PressTriggerDetector负责220ms大接触、700ms普通按住、120ms预分类和安全无文字300ms分支；PressCaptureSource统一传送门/无障碍的输入、一次读取、缓存、确认、接管及原页窗口。开关保留原保存键，不使用旧校准阈值，也不要求再次采样。

零尺寸可进入普通按住，不能称其恢复了面积数据。MOVE达到任一默认轴门槛可提前至原DOWN+220ms，尺寸回落不撤回已有峰值。每轴移动超过36px、多指、松手或取消结束未确认请求；分类结果不能将已有220ms反向拖到300ms。确认后4秒防重复，成功交接时25ms触感反馈。按住录音界面的多项提示会使本次请求退出。

普通路径120ms后读取本次内容并缓存，点中安全叶/TextView直接返正文，不再等待全树扫描才获取文本；到确认时才接管原触摸和打开窗口。已确认且正常抬手可以完成在途显示，新DOWN/位移取消会作废旧异步结果。缓存文字允许同App原生菜单换窗口ID，但显示前必须仍是同一前台应用且未锁屏；图片截图仍严格核验原窗口ID和画面尺寸。

无文字不是捕获失败的兜底：Root完整扫描、应用窗口/来源/触点/密码区域检查明确通过才返回有限ocr_region，之后截图裁剪。没有安全区域、权限失败或窗口变化保留原操作并记录原因。预分类无文字早截图区域为屏幕宽高各92%，确认后晚截图为宽78%/高34%；均裁到源应用窗口与屏幕内，不能越过密码等保护。

新增Hook仅限传送门5.1.5私有scheduleStopSelfJob，按压入口已启用时取消原空闲任务；关闭/切模式恢复原计时安排，onDestroy及系统退出保持原清理。没有增加SystemUI作用域。HyperGesture参考只读发现其用系统已有inputMonitor确认后pilfer；未发现额外面积源，本批不把其MotionEvent混入Root手势仲裁。

普通700ms路径可能晚于原App原生长按菜单，接管不能撤销已经发生的原生操作；提前缓存原文解决的是读到菜单而非原文的问题，不承诺所有页面零冲突。

以下为138过渡和历史记录，旧校准流程已撤除；构建和设备结论以DEVICE_VALIDATION最新批次为准。

## 1.7.138 过渡实现

已删除设置、Provider解释、传送门和无障碍运行时的强制校准门禁。默认按各自设备最大值归一化，接触长轴≥0.30或工具宽度≥0.095满足面积条件；有效metric2自定义校准可继续使用，未保存或旧单位阈值自动使用默认门槛。开启不打开校准页，保存自定义样本不改变开关。校准仅为既有可选诊断页，无新界面。

保留连续180ms确认及移动/多指/锁屏/黑名单处理。全零输入不触发，也没有改成普通长按。默认门槛修复的是接入和灵敏度，不能让缺失的原始轴产生数据；真实拇指输入仍未通过。参考DEX已交叉确认MI固定两路门槛及220ms加速，另有零尺寸也可进入的700ms普通长按/300ms无文字分支，不可把它当作面积恢复。

当前输入来源与参考一致：getevent能力范围、evdev48/50。未发现可解释零输入的遗漏通道；本fork在尺寸变化且坐标静止时也发送MOVE。设备切换策略不同，但已知event7坐标正常，没有证据支持盲换设备或写驱动。

以下为历史阶段记录，其中要求先校准或维持关闭的旧流程已由138替代。

## 1.7.105 历史结果

1.7.105 修正本 fork 漏读 `ABS_MT_WIDTH_MAJOR`、错误要求短轴有效的问题。现在独立读取接触长轴与工具宽度，各除以自身设备最大值，取有效值的最大值作为 0–1 归一化尺寸；校准与触发使用同一指标。旧单位阈值失效，须重新校准并手动开启。诊断显示原始长/短轴、工具宽度及三位小数归一化值。

用户确认 MI BigBang 在同一设备能触发，但过于灵敏。这个观察保留为正向行为证据，不能把本项目此前零数据推断成硬件不支持。此前原始事件记录也没有 WIDTH_MAJOR，因此本批确定修复代码缺陷，但尚不能证明真机已取得有效尺寸。新版本尚待真实手指校准。

**未通过真机验收，默认关闭。** 1.7.65 接通 Root 尺寸输入、独立校准及候选触发链路；1.7.66 修正能力提示，并增加本应用收到的 Android MotionEvent 尺寸对照。

用户真实指尖、拇指按压时，Root 坐标正常，但尺寸值无效。30 秒原始事件中有约 33 次完整触摸、367 次 X 与 300 次 Y 更新，没有 TOUCH_MAJOR/MINOR 事件。event7 声明的尺寸范围为 0–255；系统只声明轴，不代表它会在实际触摸中上报值。

用户重启 LSPosed 作用域后再次尝试，校准仍为 0/3，未产生有效阈值。新应用进程 11979 的多条日志均为长轴 0.0、短轴 0.0、size 0.000。不能将此状态误诊为阈值过高，也不能宣称普通长按已经满足面积触发。

随后用户撤回自己在系统框架中“禁用手势监控/不注册指针事件监听”的修改，重试后仍报告“没有面积数据”。这是用户操作后的对照结果，本次尚未另存对应原始事件流；它没有支持手势监控开关是原因的假设，不能因此判断触控硬件永远不支持。

## MI Big Bang 1.7.0 的只读分析

证据为用户 APK 的 JADX 输出，仅用于确认机制：

| 位置 | 观察到的行为 |
|---|---|
| C1074j7.m1479g（283–290） | 读取 getevent 能力范围，包含 TOUCH_MAJOR 与 WIDTH_MAJOR |
| C1074j7.m1480h（337–378） | 解码 evdev 接触主轴 code 48、工具宽度主轴 code 50 |
| C1042h7.m1450a（17–85） | 从活动触点获取两条轴，再结合各自最大值计算供触发判断的值 |
| p027c3/C0416e0.mo663a（46–90、203–248） | 大接触值对应 220ms，普通路径为 700ms；移动时可将截止时间提前到首次按下后 220ms；移动超过 36px 取消 |
| p027c3/C0416e0.mo663a（约183行） | 首次按下约120ms后分类，没有可读文字时可把截止时间提前到按下后300ms；这条快路径不要求面积达到门槛 |
| AbstractC1314z6.m1735g（613–653） | Root 可用时忽略传送门 MotionEvent；该回调不是尺寸来源 |
| MainHook.handleLoadPackage | android 作用域挂接背敲服务；没有看到系统输入分发器的面积 Hook |

触发比较常量为 touch 0.30 / width 0.095，任一达到即可提前安排长按。未发现面积阈值设置界面，未发现用于开启触摸驱动尺寸上报的命令。它同时有“大接触值加速长按”和“无可读文字300ms”的分支；单看图片快速触发不能证明尺寸已经有效，也不能否定用户同机观察。已核对 DEX 的 `h7.a(FFI)V`：两条比值计算均先执行 `int-to-float`，再执行 `div-float/2addr`，没有整数除法精度问题。

## 1.7.105 当时的边界

- 当前候选使用上述归一化接触尺寸，先从真实指尖/拇指样本产生独立门槛；传送门路径连续180ms确认后开始取内容，无需等松手。该语义与参考 APK 的长按加速存在差别，均须依赖真实尺寸输入。
- 只有校准成功才允许开启；没有有效尺寸时不生成默认阈值，也不静默变成长按。
- 只在明确触发后读一次节点或截取所选区域；不在无障碍事件回调中持续取词。锁屏、多指、黑名单与异步结果过期会取消；传送门模式的Root取词接线见下文；无障碍模式仍须手动启用该服务。
- 小爱 OCR、系统背敲、拖拽样式与面积输入是不同能力，Hook 安装成功不证明它们均可用。
- 后续只读核对真实驱动的数据来源和开关条件；不靠修改权限、盲写 sysfs 或叠加猜测中的 ROM 分支掩盖缺失数据。

## 1.7.109：传送门面积触发接线（尚未实机通过）

补齐受限Provider中的面积配置，传送门进程使用与校准页相同的版本和阈值，不再读取传送门自身私有偏好。仅已校准且开启时创建PortalThumbCaptureSource；设置变更重建输入协调，不新增作用域。无障碍服务只在无障碍模式接管，避免两个来源同时触发。

大接触连续180ms后可用定时器确认，不需等下一次MOVE或松手；移动超限、尺寸下降、多指取消和锁屏会使请求失效。Root文字候选通过现有分类器读取，并经模块Provider在原界面请求分词窗。只有取得安全的文字候选才尝试取消原触摸；黑名单/密码候选不先取消原操作。Root路径的图片识字尚未接通，不能据旧无障碍图片路径标为完成。

**尚有明确性能缺口：** 目标机独立`time env CLASSPATH=... app_process ...`单次约0.88秒，超过常规长按窗口；当前实现丢弃超过系统长按截止时间的结果，保留原手势，不能宣称面积触发已可用。下一步需预先启动子进程并按需连接/读取，缩短真实触发后的启动成本，同时验证空闲无节点遍历与旋转恢复问题。

170项单测、lint和构建已通过；校准仍无有效真实样本，保持关闭。不能用注入尺寸替代用户校准，不能把0.88秒单次取词当成已达到视频中的响应速度。

## 1.7.110：预热取词进程与候选分阶段通知

### 最终实现

仅在面积功能已校准且开启时预先启动Root子进程并建立UiAutomation连接，使用DONT_SUPPRESS_ACCESSIBILITY_SERVICES。不在事件回调或空闲循环中遍历节点；事件只通知正在等待的显式请求。关闭面积功能、停止作用域或父进程关闭管道后，子进程收到EOF退出，通过Binder死亡释放系统连接。

持续连接用于避免反复连接/断开导致Compose语义树暂时成为空壳。退出不调用会恢复启动时旋转状态的disconnect，避免覆盖会话期间的用户新设置；这条清理路径已在当前ROM验证。此前每请求短连接方案未采用，不能继续把“空闲无连接”作为本版本行为。空闲有连接，空闲无节点遍历。

请求先只沿触点所在分支读取。叶节点或已完整检查子树的TextView/编辑控件可发送不含正文的candidate通知。模块及时尝试取消原页面长按；随后仍遍历完整节点树，返回完整文字和相邻候选，不削减为只读单词。可点击span的TextView会检查整个子树，密码、黑名单和窗口变化校验继续保留。晚于原生长按截止时间的候选保留系统原操作并提示原因。接管触摸失败不关闭健康的取词进程。

### 当前设备证据

- 普通长按设置为300ms；面积确认仍为180ms。
- bilipai同一93个UTF-16字符评论（Python计数92），连续四次早期候选到达82/84/90/91ms；完整结果249–355ms，128个节点，四次均命中相同正文与边界。
- 返回相邻候选长度16与3；尚未验收是否应过滤用户名/回复按钮，不能当作“相邻正文段落”通过。
- 会话空闲时dumpsys显示Ui Automation，EOF退出后该条目消失。会话中将自动旋转改为关闭，退出后新值仍保留；最后恢复测试前1/0设置。
- 未修改无障碍服务开关。真实面积校准仍无数据，保持关闭；Root取消原生长按的实际成本和完整手指流程未验。180ms+候选延迟仅留下约29–38ms接管窗口，不能仅凭读取加速宣称整链路成功。

后续应继续解决真实接触数据与输入接管时序；并行推进AICR产品验收、Miuix页面与中转站实际拖放，不把仍缺手指样本的一项当作全项目阻塞。

## 1.7.117：Root图片候选分支

Root返回真实Bitmap的图片内容，按所选节点裁剪，再经既有暂存RPC打开独立图片OCR窗。普通空白View不作为图片；图片须等完整密码扫描通过，不发送早期candidate。文本/图片分别尊重对应内容开关。截图后校验来源窗口及锁屏，显示尺寸使用WindowManager.getMaximumWindowMetrics，与整屏截图坐标保持一致；首轮误用资源DisplayMetrics导致拒绝，已修正根因。

生成ImageView在真机取得1392×773区域并经AICR显示83字符分词，关闭恢复原页。该实验仅验证图片取用链，不包含真实面积触发、Portal UID、原手势接管和300ms截止时间；真实尺寸无有效样本，功能继续关闭。复杂页面图片不能利用文字早通知的速度，仍可能因超时保留原长按。

## 1.7.121：帧顺序与迟到候选修正

EvdevTouchParser保留本帧先于TRACKING_ID或BTN_TOUCH报告的坐标、长轴和工具宽度，只清理上一次接触遗留的数据。增加轴先到的回归用例，保留多指取消与新接触尺寸清零。该缺陷不能解释已有零尺寸：复核旧记录34个DOWN帧均为BTN、TRACKING、X/Y在前，未出现MAJOR/WIDTH事件；约33次完整触摸。当前只读能力表event7仍声明TOUCH_MAJOR最大255，未声明WIDTH，不能等同实际上报。

面积确认后移动超限或尺寸下降，立即让本次异步候选过期，停止触摸接管；同一手势不因回到原位重新触发。已确认后正常UP仍允许已取得所有权的结果结束。新增3个状态回归用例；连同解析器用例共186项测试通过。真实面积、迟到候选的实际手指接管仍未通过，保持关闭。

新增的主动点取使用独立显式点击，不伪造尺寸，也不改变上述结论。它与已开启的面积预热会话目前可能争用唯一UiAutomation注册位；当前明确报占用，不抢断其它会话。准备/取消和具体证据见POINT_CAPTURE.md。

## 1.7.126：共用取词连接

面积预热与手动点取改为向模块Provider申请各自的Binder租约，模块进程只启动一份RootNodeCaptureMain。手动租约存在时不接受自动请求，手动关闭后保留自动预热；最后租约关闭或所属进程死亡才释放。两个进程的复用、优先级、关闭与死亡释放已有真机证据，不再将两种自有入口视作外部UiAutomation冲突。

只有用户明确触发后才读取节点，空闲只维持连接。仍不允许uiautomator dump与该连接同时使用，不断开外部自动化；真实面积数据仍为缺口。Provider引导与租约接口不改变尺寸来源，没有新增输入框架Hook，也没有假校准。本版不能作为真实拇指或bilipai普通长按已修复的证据，详见POINT_CAPTURE与DEVICE_VALIDATION。

## 1.7.132 后的定点复核（只读）

再次只核对已定位链而不全量重新反编译。观察：C1074j7:254读取/proc/bus/input/devices，:272–274读取选中event，:285 getevent -lp读取能力，:337–378解码48/50；C1042h7:48/66归一化，C0416e0:66–77、215–223消费Root尺寸。AbstractC1314z6.m1735g:613–653的MotionEvent不读取尺寸，Root可用时忽略；候选设备切换依据是事件沉默，不是尺寸为0后开启新驱动。指定链未发现sysfs写入、input设置、ioctl或另一SDK尺寸来源。
