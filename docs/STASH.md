# 本 fork 的中转站

目标是连续收集、快速确认和取用文字/图片。基于本仓库独立实现；参考资料只用于研究交互。

当前1.7.116：原生系统小窗与侧窗均支持按住内容直接拖出。默认侧窗仍不超过屏幕1/6，直接按住文字/缩略图即可拖出，点按分词/预览。另一UID的诊断接收器已实际收到单条文字、PNG以及混合六项；这里只证明当前ROM和该接收器，不代表所有应用支持拖拽。

## 当前代码

- `StashStore` 在应用私有 SQLite 中保存条目，图片复制进 `files/stash`，不依赖临时分享图片的过期时间。列表按新到旧排列。
- 传送门拖拽菜单的内置“中转站”经限定调用方的 Provider RPC 存入；该路径接通，尚需真实传送门拖拽验收。
- 设置中打开 Miuix 列表，系统分享可导入文字/单张图片；卡片提供分词/预览、复制、分享、删除及 Android 原生拖出。
- 多选可全选/取消、批量分享或确认删除。纯文本按换行拼接，图片使用多项 URI 和读取授权；混合输出携带文字与图片，接收方是否支持混排须逐应用验证。
- 持久图片 Provider 不导出，外部接收者必须获得用户本次分享/拖拽所给的 URI grant。对不存在的条目、读取失败和权限失败给出明确原因，不改变系统组件权限。
- 1.7.70 源码将同一页面的分享导入串行执行，图片限制为 32 MiB；超限会说明原因并清理不完整文件。已通过源码检查与单测，尚未安装，不能当作设备已有行为。

## 待验证：HyperOS 系统小窗（用户新增方向）

用户提出接入 HyperOS 小窗以支持放大缩小。当前 StashOverlayPanel 是 TYPE_APPLICATION_OVERLAY，不是系统管理的 Activity 任务，不能只加 resizeableActivity 就获得系统小窗行为。Android 多窗口支持是必要基础，不证明 HyperOS 4 的主动小窗启动入口可用。

拟定交互：日常保持灰色侧条与面积不超过1/6的取用窗；用户主动放大时进入独立中转站系统小窗，复用数据与条目操作，缩回时返回侧条。仅展示中转站内容，不打开设置首页。系统小窗技术上仍有Activity任务，是否接受此形式按用户当前提议推进研究。

准入验证：目标ROM实际小窗启动入口、大小限制、最小化/恢复、焦点与输入法、跨应用拖出、开始拖出时让开目标窗口。不能宣称系统小窗可缩到1/6；该限制仍由默认取用窗保证。在入口核验和设备测试前不暴露无效按钮，不猜测私有Intent参数。

Android基础参考：https://developer.android.com/develop/ui/views/layout/support-multi-window-mode

## 1.7.115：直接按住内容拖出与新内容置顶

- 默认紧凑侧窗移除每条独立40dp“按住拖出”行。文字/图片内容直接长按启动Android全局拖拽，点按仍分词/预览；复制按钮独立。多选时内容点击只切换选择，统一底部拖出所选。系统小窗与管理列表保留原拖出入口，共用数据和预览构造。
- 拖拽影子使用文字摘要或图片/项目数，避免把“按住拖出”提示当内容影子。遵循Miuix当前前景/容器色，最多3行。拖出成功才收起；系统拒绝与权限失败显示原因，不修改系统权限。
- ClipDescription保留各图片实际MIME（如image/png、image/jpeg）和文字类型；原来仅声明image/*，会导致只查询具体类型的接收方无法匹配。混合项目顺序与URI读取授权保持；新增一项协议测试覆盖具体/通配匹配及项目顺序。
